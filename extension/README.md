# RefineID browser extension (MV3 prototype)

Pairs a phone over the RAPP `relay-websocket-v1` transport and opens
card-backed sessions. The service worker owns the relay WebSocket legs
and pumps frames through the WASM requester (`../wasm-requester/`);
all RAPP state lives in WASM memory.

Apache-2.0, like the rest of this repository.

## Layout

- `manifest.json` - MV3 manifest (module worker, popup, page bridge).
- `worker.js` - relay legs, pairing/session flows, message API.
- `protocol.js` - minimal deterministic-CBOR join frames (also used
  by the Node tests).
- `popup.html`, `popup.js` - pair code, grants, pairs, session start.
- `bridge.js` - content-script page API on RefineID-owned origins.
- `wasm/` - build output, regenerated by the script below. Not committed.

## Build

```sh
./scripts/build-extension-wasm.sh
```

Then load `extension/` unpacked in Chrome (`chrome://extensions`,
developer mode). Point the popup at a relay: the local PoC relay
(`../relay/`, `ws://127.0.0.1:9443`) is the default.

## Message API (worker)

- `{type:'status'}` - worker/pairs/flow/session snapshot.
- `{type:'pair', relayUrl}` - start pairing, returns `{code, formatted}`.
- `{type:'grants', grants}` - confirm phone grants, finishes pairing.
- `{type:'session', pairId, relayUrl}` - open a session leg.
- `{type:'close'}` / `{type:'cancel'}` - drop session / abort flow.

Errors come back as `{error: string}`; worker state keeps `lastError`.

## Page bridge

Pages on `https://card.refineid.fi` (and localhost `:8080` for dev)
can `window.postMessage({channel:'refineid-extension-v1', id, method,
params})` to the content script. Served methods: `status` (worker
snapshot), `session` (needs `params.pairId` + `params.relayUrl`),
`close` (drop the session). Replies arrive as `{channel, id, reply}`
or `{channel, id, error}`. Every other method answers `deferred
method`. Third-party site access is deferred.

`../public/login.html` is a demo relying party on `:8080` that runs
the login ceremony through this bridge; see `../LOGIN.md`.

## Proto limits

- Pairs live in WASM memory: a worker restart drops them.
- Noise KK completes on m2; the worker never writes m3.
- `host_permissions` allow any `wss` relay plus local `ws`. A
  production build narrows this to the deployed relay host (the relay
  operator is still undecided).
- Operations (login/signing envelopes over the established leg) ride
  in the next slice.
